# HAR-008 bounded trusted report scanning

## Scope

Issue [#20](https://github.com/keyforta/keyforta-property/issues/20) approves a
bounded correction for HAR-007's final resource-exhaustion blocker.

## Business invariant

Attacker-controlled candidate evidence must preserve its entry types across the
handoff and must not escape extraction, race scanner traversal, or cause
unbounded allocation in the trusted retention workflow.

## Failure

Directory enumeration buffers all entries before enforcing the count limit, and
whole-file reads do not revalidate per-file or aggregate limits against opened
descriptors. Same-inode growth can therefore exceed declared bounds.

## Design

Consume directory entries incrementally from descriptor-rooted handles. Read
regular file descriptors in fixed chunks with a one-byte overflow probe, enforce
per-file and aggregate budgets against opened descriptors, and retain only the
bounded exact bytes that passed scanning.

PR CI packages reports with system tar so links remain links rather than being
dereferenced by artifact globbing. Trusted default-branch code downloads the
artifact ZIP with compressed and expanded byte limits, then validates and
extracts only unique, relative regular files and directories within the same
depth, entry, file, and aggregate limits before descriptor-rooted Linux scanning.
Raw ZIP and tar header preflights enforce entry bounds before high-level parsers
can allocate their complete member indexes; extended tar metadata is rejected.

## Acceptance-test map

| Acceptance criterion | Requirement | Verification |
| --- | --- | --- |
| `AC-HAR-008-01` | Enumeration and descriptor reads are bounded. | Entry-count and same-inode growth regressions on macOS and Linux Node 24 |
| `AC-HAR-008-02` | Candidate types and scanned bytes remain exact through retention. | Link-preserving archive rejection, multibyte buffer comparison, hidden-file workflow assertion, and canonical verification |

## Threat model

An untrusted pull request controls artifact entry count, hierarchy, metadata,
timing, and bytes. It may race regular files after enumeration or use sparse and
growing files. The trusted scanner must bound work at directory iteration and
opened-descriptor reads, fail closed on limit violations, and upload no partial
snapshot.

The artifact service may otherwise dereference report links before trusted code
observes them. Archives may also contain absolute or parent paths, duplicates,
links, devices, malformed payloads, or excessive entries and bytes. Extraction
rejects those forms and removes all partial output. Production scanning fails
closed off Linux because Node cannot enumerate a directory through `/dev/fd` on
macOS without reopening its mutable path.

## Security

The trusted downloader receives the workflow's ephemeral `actions: read` token
only for the run-scoped GitHub API request and strips authorization before a
cross-host signed-download redirect or any HTTPS downgrade. Existing trusted
action pins, read-only repository permissions, path/symlink controls, and
exact-byte snapshot ownership remain unchanged.

## Tests

The focused suite rejects link-bearing and duplicate-root candidate archives,
1,001 entries during incremental enumeration, static oversized files,
same-inode growth before open, and growth injected after the first read chunk.
An end-to-end tar, extraction, scan, and snapshot regression compares hidden
multibyte UTF-8 buffers. Workflow structure also requires hidden sanitized files
to be uploaded. Direct downloader regressions reject multi-entry ZIPs and prove
authorization removal on cross-host redirects and HTTPS downgrades. Existing
encoding, symlink, FIFO, nested report, and secret regressions remain green.

## Results

The focused harness suite passes on macOS and Linux Node 24. Contract validation,
14-path security classification, workspace checks, production build,
infrastructure validation, and full canonical verification pass. Independent
reviews and exact-head GitHub checks remain required before merge.

## Repair cycle

Independent security review found that the initial chunk reader threw before
charging an overflow chunk, lacked direct aggregate/depth regressions, and could
leak a directory descriptor when metadata validation threw. Repair cycle one
charges every successful read before overflow evaluation, closes descriptors on
all metadata exceptions, and adds aggregate-growth and depth fixtures on macOS
and Linux Node 24.

Fresh Copilot review found that artifact globbing dereferenced report symlinks,
the scanner's non-Linux fallback reopened a mutable path, the retained artifact
could omit hidden files, and the exact-byte regression compared decoded text.
Repair cycle two replaces the raw-directory handoff with a link-preserving tar,
adds bounded ZIP download and trusted bounded extraction, counts and rejects
duplicate archive roots, opens the tar once with no link following and bounded
reads, preflights raw ZIP and tar entry counts, aligns extraction depth with the
scanner, fails production scanning closed off Linux, includes hidden snapshot
files, and compares multibyte source and snapshot buffers exactly.

## Bounded correction

The correction changes only candidate packaging, trusted artifact download and
extraction, scanner platform enforcement, exact artifact upload settings, and
adversarial tests. It does not alter retention provenance,
permissions, action pins, secret policy, product behavior, data, infrastructure,
deployment, or migration boundaries.
