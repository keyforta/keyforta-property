# HAR-008 bounded trusted report scanning

## Scope

Issue [#20](https://github.com/keyforta/keyforta-property/issues/20) approves a
bounded correction for HAR-007's final resource-exhaustion blocker.

## Business invariant

Attacker-controlled candidate evidence must not cause unbounded allocation in
the trusted retention workflow.

## Failure

Directory enumeration buffers all entries before enforcing the count limit, and
whole-file reads do not revalidate per-file or aggregate limits against opened
descriptors. Same-inode growth can therefore exceed declared bounds.

## Design

Consume directory entries incrementally from descriptor-rooted handles. Read
regular file descriptors in fixed chunks with a one-byte overflow probe, enforce
per-file and aggregate budgets against opened descriptors, and retain only the
bounded exact bytes that passed scanning.

## Acceptance-test map

| Acceptance criterion | Requirement | Verification |
| --- | --- | --- |
| `AC-HAR-008-01` | Enumeration and descriptor reads are bounded. | Entry-count and same-inode growth regressions on macOS and Linux Node 24 |
| `AC-HAR-008-02` | Scanned bytes remain exact snapshot bytes. | Harness self-test, byte comparison, and canonical verification |

## Threat model

An untrusted pull request controls artifact entry count, hierarchy, metadata,
timing, and bytes. It may race regular files after enumeration or use sparse and
growing files. The trusted scanner must bound work at directory iteration and
opened-descriptor reads, fail closed on limit violations, and upload no partial
snapshot.

## Security

HAR-008 adds no credential or secret access. Existing trusted-workflow action
pins, read-only repository permissions, path/symlink controls, and exact-byte
snapshot ownership remain unchanged.

## Tests

The focused suite rejects 1,001 entries during incremental enumeration, static
oversized files, same-inode growth before open, and growth injected after the
first read chunk. Existing encoding, symlink, FIFO, nested report, secret, and
exact-snapshot regressions remain green.

## Results

The focused harness suite passes on macOS and Linux Node 24. Contract validation,
12-path security classification, workspace checks, production build,
infrastructure validation, and full canonical verification pass. Independent
reviews and exact-head GitHub checks remain required before merge.

## Repair cycle

Independent security review found that the initial chunk reader threw before
charging an overflow chunk, lacked direct aggregate/depth regressions, and could
leak a directory descriptor when metadata validation threw. Repair cycle one
charges every successful read before overflow evaluation, closes descriptors on
all metadata exceptions, and adds aggregate-growth and depth fixtures on macOS
and Linux Node 24.

## Bounded correction

The correction changes only trusted scanner resource accounting, descriptor
cleanup, and adversarial tests. It does not alter retention provenance,
permissions, action pins, secret policy, product behavior, data, infrastructure,
deployment, or migration boundaries.
