## Requested outcome

Expose a narrow KEYFORTA Model Context Protocol endpoint from its own deployable
service so approved Claude and ChatGPT-compatible clients can consume it over
Streamable HTTP. Scaffold a reusable App SDK tool and widget platform while the
first slice remains limited to server metadata and a synthetic read-only
health/capability tool with an isolated React widget.

No model provider is called by this slice. It does not expose tenant or business
data, access PostgreSQL, accept organization context from a client, add a write
tool, provision secrets, create public ingress, activate a paid service, or
deploy to production.

## Product evidence

`docs/product/IMPLEMENTATION_PLAN.md` places grounded assistance in Increment 5
and requires read-only tools, evidence references, authorization evaluation, and
AI-unavailable fallback behavior. `docs/ai/AI_SYSTEM_CARD.md` permits authorized
retrieval and explanation while prohibiting autonomous business outcomes.

`docs/ai/TOOL_POLICY.md` requires narrow business capabilities, application-
established actor and organization context, minimum authorized fields, explicit
application confirmation for consequential writes, correlated audit records,
and untrusted-output handling. ADR-007 keeps AI advisory and requires model,
provider, policy, source, time, and human-action traceability for AI outputs.

## Superseded design

`docs/engineering/REQUIREMENTS_GAPS.md` explicitly defers AI feature activation
pending Product Owner and AI/security review. In addition,
`docs/architecture/AZURE_ARCHITECTURE.md` exposes only the web application and
keeps the Fastify API private. A remotely reachable MCP endpoint therefore needs
an approved placement and authentication design before implementation.

The Product Owner approved the bounded capability. The earlier Architecture and
Security/Privacy decision placed `/mcp` inside the existing private API for
local/test use. That placement is superseded by the explicit requirement that
MCP run as its own deployable service and never live within `apps/api`.

The uncommitted API-local runtime, tests, and dependencies were removed. No MCP
runtime remains under `apps/api`.

Public ingress, production activation, OAuth/client registration, paid
services, provider credentials or calls, tenant-data tools, write tools, and
provider data-processing remain excluded and separately gated.

## Business invariant

The model or MCP client must never establish actor or organization scope, access
the database directly, receive unauthorized data, or autonomously complete a
business decision. Deterministic KEYFORTA workflows must remain usable when MCP
and model clients are unavailable.

## Required design

Proposed ADR-012 defines:

- `apps/mcp-server` as an independent TypeScript deployment unit and public MCP
  resource boundary;
- Turborepo as a cache-bounded orchestrator over the existing pnpm workspace;
- dependency-free `packages/types`, runtime schemas in `packages/contracts` or
  owning tools, widget-specific `packages/ui-core`, and shared
  `packages/build-utils`;
- isolated `tools/<domain>/<tool-name>` packages and standard
  `ui://keyforta/...` widget resource URIs;
- dual-layer tool responses whose `_meta` is model-hidden but still subject to
  browser authorization and data minimization;
- Microsoft Entra authentication, mandatory cloud-connector interoperability
  proof, and delegated on-behalf-of exchange for future private API calls;
- one-replica ephemeral sessions, inactive IaC, network isolation,
  observability, cost controls, operational ownership, and rollback.

ADR-012 is accepted for implementation planning by Product, Architecture,
Security/Privacy, UX, and Platform/SRE. AI-001 remains a preserved blocked
record because the EDD policy has no transition out of `blocked`; runtime and
dependency work proceeds only through separately routed successor contracts.

## Tradeoffs

An independent deployment provides isolation, scaling, and release ownership,
but adds network authorization, deployment, observability, cost, availability,
and session-distribution complexity. The package platform adds build graph,
Storybook, localization, iframe bridge, CSP, and accessibility maintenance.
ADR-012 records the public protocol, identity, widget, provider compatibility,
and independent shutdown boundary as the measurable exception to ADR-001.

Canonical tests prove MCP Streamable HTTP protocol compatibility suitable for
conforming Claude and ChatGPT clients. They do not claim live connector or OAuth
compatibility because provider credentials and public ingress are excluded.

## Threat model

| Threat | Fail-closed control | Evidence |
| --- | --- | --- |
| Identity or organization spoofing | Inject immutable identity before MCP dispatch; ignore identity fields in JSON-RPC content | Authentication and override tests |
| DNS rebinding or browser cross-origin use | Exact Origin allowlist; reject malformed, `null`, and unlisted origins | Origin table tests |
| Session theft or replay | Opaque IDs, authentication on every request, actor/origin binding, explicit close, bounded expiry | Session mismatch, close, and expiry tests |
| Protocol confusion or malformed input | Official SDK negotiation, approved protocol header, body limit, sanitized errors | Raw JSON-RPC tests |
| Data or secret disclosure | One fixed synthetic tool; exact result and audit field allowlists | Recursive forbidden-field assertions |
| Resource exhaustion | Existing API body limit plus bounded in-memory session count and expiry | Limit and shutdown tests |
| MCP or provider outage | MCP registration is optional and deterministic API workflows remain independent | Disabled-mode and shutdown tests |

## Dependency impact

No runtime or build dependency is currently authorized. A later standalone
application task may propose exact MCP SDK, React, Fluent UI, Zod, Vite,
Storybook, accessibility, and Turbo versions after ADR acceptance. It must not
add MCP, widget, provider, OAuth, or database dependencies to `@keyforta/api`.

## Tests

| Criterion | Deterministic verification |
| --- | --- |
| `AC-AI-001-01` | Initialize a stateful Streamable HTTP session, send initialized notification, list exactly one tool, call `keyforta_health`, and close the session using the SDK-compatible protocol. |
| `AC-AI-001-01` | Negotiate a supported initialize version and reject unsupported subsequent `MCP-Protocol-Version` headers. |
| `AC-AI-001-02` | Reject missing/invalid identity before dispatch on POST, GET, and DELETE; request body identity fields cannot override the injected actor. |
| `AC-AI-001-02` | Allow exact configured or absent non-browser Origin and reject malformed, `null`, and unlisted origins. |
| `AC-AI-001-02` | Reject missing, unknown, actor-mismatched, origin-mismatched, closed, and expired sessions without invoking the tool. |
| `AC-AI-001-02` | Sanitize malformed JSON-RPC, invalid tool arguments, unknown tools, and internal failures while preserving a server correlation ID. |
| `AC-AI-001-02` | Assert exact tool/result/audit shapes and recursively reject business, identity, prompt, credential, session, stack, database, and secret fields. |
| `AC-AI-001-02` | Close transports on app shutdown and prove MCP remains absent unless explicitly enabled outside production. |

## Rollback

Remove MCP registration, source, tests, and direct dependencies, then regenerate
the lockfile. In-memory sessions disappear on shutdown. No data migration,
remote resource, credential, provider call, or deterministic workflow changes
require rollback.

## Acceptance boundary

The bounded implementation must prove that:

- an authenticated Streamable HTTP client can initialize, negotiate a supported
  MCP protocol version, list tools, invoke only the synthetic health/capability
  tool, and close or expire its session;
- unauthenticated, malformed, invalid-session, unsupported-origin, and
  unsupported-protocol requests fail closed with sanitized responses;
- tool schemas and results contain no organization, user, property, unit, lease,
  tenant, payment, maintenance, document, prompt, credential, or secret data;
- bounded correlation and audit metadata cover successful and denied requests;
- deterministic offline tests demonstrate protocol behavior and client
  compatibility without paid services or external credentials;
- focused API checks and canonical `pnpm verify` pass.

## Reason

The mandated independent deployment supersedes the approved API-local design and
introduces a consequential architecture and infrastructure decision. Accepted
ADR-012 satisfies the architecture design gate; implementation and deployment
remain separately governed.
