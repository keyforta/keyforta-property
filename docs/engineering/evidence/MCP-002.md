## Business invariant

The connector, model, tool input, widget, and `_meta` channel cannot establish
actor or organization authority, receive credentials, or bypass application
authorization. This slice exposes synthetic service metadata only.

## Implementation plan

1. Define the strict synthetic health/capability tool and validated split result
   in its owning package with an injected clock.
2. Add a standalone Fastify MCP application using the official SDK,
   authenticated request injection, exact origin checks, bounded bodies, and
   sanitized correlated errors.
3. Register tools and `ui://` resources explicitly and fail startup on duplicate
   names, resource URIs, or contract versions.
4. Serve Streamable HTTP initialize, tool listing/call, and widget resource read
   behavior with bounded authenticated sessions.
5. Add handler, registry, HTTP denial, protocol, shutdown, and safe-channel
   tests, then run audit and canonical verification.

## Authentication boundary

Tests inject a synthetic authenticator. Local development accepts only a fixed
synthetic bearer marker and grants only `mcp:health`; it carries no real user or
tenant authority. Production startup fails closed until a separately approved
Entra authenticator is supplied.

## Exclusions

No Entra registration or token implementation, OAuth metadata activation,
private API call, OBO exchange, tenant data, model-provider call, public ingress,
infrastructure, credential, paid service, or deployment is included.

## Rollback

Remove the server package and health tool runtime files and regenerate the
lockfile. No persisted data or remote resource requires rollback.

## Implementation evidence

- `apps/mcp-server` is an independent deployable and does not import
   `apps/api`, database code, authentication internals, or provider clients.
- The SDK registry publishes exactly `keyforta_system_health` and
   `ui://keyforta/system/health`; duplicate identifiers and unsupported contract
   versions fail startup.
- Streamable HTTP sessions are bound to the authenticated principal and origin
   class and supported negotiated protocol version, with atomic admission, idle,
   absolute, count, body-size, concurrency, and request-time limits. Long-lived
   GET streams do not consume POST/DELETE capacity.
- The local authenticator recognizes one synthetic bearer marker and grants
   only `mcp:health`. It requires explicit opt-in and loopback binding.
   Production authentication selection throws until an approved Entra
   authenticator exists.
- Telemetry is injected and limited to event name, request ID, status, tool
   name, and resource URI. Correlation IDs are server-generated and synchronous
   or asynchronous telemetry failures cannot affect protocol availability.
   Tests verify bearer values and rejected tool input do not enter errors or
   telemetry.
- Tool validation and unexpected execution errors return stable correlated
   results without schema fields, input values, or runtime details.
- The production build copies the self-contained widget into the MCP artifact;
   runtime startup has no repository-relative widget dependency.
