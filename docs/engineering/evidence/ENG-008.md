# ENG-008 task-specific evidence

## Scope

Replace shared validation-document coupling with one contract-owned Markdown
evidence file per task. Generated reports remain under `harness/reports/`.

## Requirements

Task contracts select `docs/engineering/evidence/TASK-ID.md`. Existing
contracts may continue referencing the legacy shared document until migrated.

## Risks

Evidence selection must remain deterministic, hash-bound, section-bound, and
fail closed when a required reference is missing or ambiguous.

## Unknowns

No product, runtime, data, infrastructure, or deployment behavior is affected.

## Design

The evidence generator resolves exactly one contract-declared Markdown evidence
reference and uses it for classification and terminal verification artifacts.

## Tradeoffs

Legacy compatibility avoids a repository-wide migration in this change. New
tasks gain isolated evidence files at the cost of one small file per task. The
legacy fallback is limited to the task IDs already using the shared document.

## Rollback

Revert the selector and regression tests. Existing legacy contracts continue to
work throughout the rollout.

## Steps

1. Add strict task evidence selection with legacy compatibility.
2. Bind generated artifacts to the selected reference.
3. Cover unique, missing, and ambiguous references in the harness self-test.

## Tests

The deterministic self-test verifies task-specific artifact references and
rejects missing or ambiguous Markdown evidence declarations.

## Results

The task contract is valid and the deterministic harness self-test passes with
coverage for unique task evidence selection and missing or ambiguous reference
rejection. Canonical results are recorded in the generated task report.

## Coverage

The change covers configuration, dependency, and terminal verification artifact
generation without changing artifact section validation.

## Security

Path confinement, regular-file checks, symlink rejection, SHA-256 binding, and
substantive-section validation remain enforced.

## Accessibility

No user interface behavior changes.

## Architecture

Evidence remains owned by the harness; task files become independent instead of
sharing a mutable documentation artifact.

## Infrastructure

No infrastructure behavior changes.
