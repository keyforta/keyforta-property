# HAR-009 adopt trusted retention boundary in PR #13

## Scope

Issue [#21](https://github.com/keyforta/keyforta-property/issues/21) approves
integration of PR #19's merged trusted retention boundary into PR #13.

## Business invariant

Untrusted pull-request code must produce candidate evidence without deciding,
filtering, or uploading the retained bytes.

## Failure

PR #13 predates merge commit `b49df918bf3b0467c5207cd402da3d50c67bd202`
and conflicts with its workflow, scanner, and lifecycle regressions. Four open
Copilot threads identify PR-controlled scanner provenance, recursive ownership
of an untrusted report root, blocking special-file opens, and skipped entries
after an earlier finding. HAR-003, HAR-005, and HAR-006 cannot receive another
repair because each is at cycle three.

## Design

Preserve PR #13's isolated unprivileged producer, but adopt `main` as the source
of trusted report packaging, download, extraction, descriptor scanning, and
snapshot behavior. PR #13 selects HAR-009 and uploads only the tar candidate;
the protected `workflow_run` owns all retention decisions.

## Threat model

The PR controls repository code and report entries but has no secrets or write
token. It may replace roots or leaves with links and special files, race reads,
or submit excessive archive metadata. Candidate packaging preserves entry types;
trusted bounded extraction and Linux descriptor traversal reject unsafe forms.

## Bounded correction

This task resolves only the post-merge integration conflicts and review findings.
It does not alter HAR-003, HAR-005, or HAR-006 state, requirements, policy,
schema, product behavior, data, infrastructure, deployment, or migration scope.

The workflow conflict retains the producer-owned `/tmp` workspace, pnpm sealing,
and HOME/XDG isolation. It removes the frozen PR-side scanner and report-root
move/chown, stops the producer, and creates the link-preserving tar directly from
the isolated workspace. Scanner and lifecycle conflicts use the reviewed `main`
implementation; the lifecycle suite adds integration assertions for HAR-009,
producer isolation, and raw candidate handoff.

## Repair cycle

Repair cycle one adds the successful CI `dependency-audit` result to the checks
supplied during final transition validation. Offline verification continues to
record that network-dependent gate as skipped instead of fabricating a pass. It
also narrows allowed paths to the effective PR diff, requires producer termination
before packaging and upload, and corrects rollback to the merged mainline baseline.

Repair cycle two fails closed when producer termination cannot be proven. The
root-owned stop step locks the account, kills remaining processes, verifies none
remain, and creates a marker required by packaging. It also removes the unused
`.gitignore` authorization from the task contract.

Repair cycle three replaces racy UID process enumeration with a dedicated cgroup
v2 boundary. Every producer command enters the cgroup; the stop step locks the
account, invokes `cgroup.kill`, proves `populated 0`, removes the empty cgroup, and
creates a root-only control marker. Packaging requires successful stop, and upload
requires successful stop and packaging outcomes, so partial archives are not
retained.

## Results

The conflict-marker and JavaScript syntax checks pass. The full harness self-test
passes, including trusted-workflow provenance, tar extraction, hidden multibyte
bytes, symlink/FIFO races, independent entry scanning, producer HOME/XDG state,
sealed pnpm tooling, bounded workspace ownership, and HAR-009 selection. Contract
and security classification validation pass. The full lifecycle suite also passes
on Linux with Node 24 and Python 3.11. Local offline canonical verification reaches
the evidence gate and correctly refuses to mark the CI-only dependency audit as
passed. CI-mode canonical passes every executable gate, including the production
dependency audit, then correctly requires a clean committed worktree for SHA-bound
evidence. Clean-head CI-mode canonical verification and SHA-bound evidence pass at
commit `7fe7f3f` before the cgroup correction. Cycle-three focused lifecycle,
contract, and classification checks pass locally; cgroup execution is structurally
validated but requires GitHub's Ubuntu runner. Regenerated cycle-three SHA evidence,
GitHub exact-head CI, and the protected retention canary remain required before
merge.
