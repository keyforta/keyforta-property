# HAR-011 prove package guard ordering and blocked transition evidence

## Scope

Issue [#23](https://github.com/keyforta/keyforta-property/issues/23) authorizes
the bounded correction of two proof defects remaining after HAR-010. HAR-010
remains blocked at repair cycle three and its history is immutable.

## Requirements

The lifecycle suite must prove every workspace and harness directory and
anti-symlink guard executes before privileged candidate tar traversal. Canonical
evidence generation must emit the policy-required state-change record for a
valid terminal blocked transition, including reason, actor, timestamp, and
evidence references.

## Failure

The HAR-010 lifecycle regression checked package guard strings only by presence,
so it could pass when guards moved after `tar` or appeared in comments. Canonical
verification of HAR-010 also failed because `transitionArtifactRecords` emits
records only for `changes-requested -> implemented`, while the policy requires a
state-change record for a terminal blocked transition.

## Design

Parse the package step into executable command lines and require the exact four
root guard commands, in order, before the exact privileged tar command. Extend
transition artifact generation to select the policy transition represented by
the final two history states, including `implemented -> blocked`, while keeping
the existing evidence-reference and section allowlists fail closed.

## Tradeoffs

Exact command ordering is intentionally strict because this is a privileged
security boundary. Generalizing transition record generation slightly broadens
the helper, but policy remains the authority for which transitions and sections
are permitted.

## Steps

1. Add negative package-step fixtures for missing, commented, reordered, and
   post-tar guards.
2. Add blocked-transition artifact generation and malformed-evidence tests.
3. Select HAR-011 in PR #13 CI without changing runtime containment or retention.
4. Run focused tests, canonical verification, exact-head CI, and protected

## Risks

Over-broad transition generation could fabricate evidence for unsupported state
changes. Tests must prove both paths fail closed under mutation.
