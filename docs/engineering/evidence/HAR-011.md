# HAR-011 prove package guard ordering and blocked transition evidence

## Scope

Issue [#23](https://github.com/keyforta/keyforta-property/issues/23) authorizes
the bounded correction of two proof defects remaining after HAR-010. HAR-010
remains blocked at repair cycle three and its history is immutable.

## Requirements

The lifecycle suite must prove every workspace and harness directory and
anti-symlink guard executes before privileged candidate tar traversal. Canonical
evidence generation must emit the policy-required state-change record for a
valid terminal blocked transition, including reason, actor, timestamp, and
evidence references.

## Failure

The HAR-010 lifecycle regression checked package guard strings only by presence,
so it could pass when guards moved after `tar` or appeared in comments. Canonical
verification of HAR-010 also failed because `transitionArtifactRecords` emits
records only for `changes-requested -> implemented`, while the policy requires a
state-change record for a terminal blocked transition.

## Design

Parse the package step into executable command lines and require the exact four
root guard commands, in order, before the exact privileged tar command. Extend
transition artifact generation to select the policy transition represented by
the final two history states, including `implemented -> blocked`, while keeping
the existing evidence-reference and section allowlists fail closed.

## Tradeoffs

Exact command ordering is intentionally strict because this is a privileged
security boundary. Generalizing transition record generation slightly broadens
the helper, but policy remains the authority for which transitions and sections
are permitted.

## Steps

2. Add blocked-transition artifact generation and malformed-evidence tests.

## Results

On 2026-09-16, the lifecycle suite passed with positive and negative coverage
for missing, commented, reordered, and post-tar package guards. The same suite
confirmed that `implemented -> blocked` emits one complete state-change record
and that removing its required `actor` section fails validation. Syntax checks,
workspace diagnostics, and `git diff --check` also passed.

Exact-head GitHub CI, protected retention, and independent review remain pending
external gates and are not satisfied by this local evidence.

## Review correction record

### Reason

Independent security and pull-request review found that line-order validation
could accept guards inside non-executing shell control flow or alongside an
earlier alternate tar invocation. AC-HAR-011-01 was therefore not yet proven.
Final review after cycle three found that executable aliases such as `/bin/tar`
and escaped `\tar` still evade whole-job token matching. HAR-011 is blocked
because its three permitted automated repair cycles are exhausted.

### Actor

Security and Privacy Reviewer and Pull Request Reviewer identified the defects;
the Harness and Evaluation Engineer recorded the terminal blocked transition.

### Timestamp

Review corrections began at 2026-09-16T01:09:12.000Z. The terminal blocked
transition was recorded at 2026-09-16T01:23:06.000Z.

### Evidence references

The independent reviewer reports are recorded in the governing Copilot session;
the bounded repairs and regression results are recorded in this document. The
latest canonical result is preserved in `harness/reports/verify-latest.json`.

### Resolution

Repair cycle one replaced line-position membership with an exact allowlist for
the executable package commands. The lifecycle suite now rejects false-branch,
heredoc, alternate-tar, duplicate, missing, commented, reordered, and post-tar
mutations, and passes the unchanged workflow package step.

### Repair cycle

Cycle one resolved the original control-flow bypass. Cycle two addresses review
findings that Unicode whitespace was normalized before comparison and that this
required correction-record section was absent.

Cycle two preserves each YAML-parsed command byte during exact comparison and
adds a non-breaking-space mutation. The focused suite rejects that mutation and
all cycle-one bypasses. This `Repair cycle` section also completes the policy-
required correction record alongside `Bounded correction`.

Cycle three addresses the final security review finding that a second workflow
step could invoke tar outside the validated package step. This is HAR-011's last
permitted automated repair cycle.

The cycle-three implementation requires one uniquely named package step and one
tar-bearing command across the complete validation job. That command must equal
the approved candidate tar byte-for-byte. Extra-step and duplicate-package-step
mutations now fail while the unchanged workflow passes.

## Bounded correction

`transitionArtifactRecords` and `validateTransition` now resolve transition
requirements through the same evidence policy helper. Artifact generation stays
limited to correction records and terminal blocked records. Package validation
parses executable lines, ignores comments, and requires each exact guard once in
the required order before privileged tar. PR #13 now selects HAR-011 without
changing producer containment or trusted retention behavior.

## Risks

Loose string matching could preserve a false-positive security regression.
Over-broad transition generation could fabricate evidence for unsupported state
changes. Tests must prove both paths fail closed under mutation.
