# HAR-010 preserve governed environment through cgroup launcher

## Scope

Issue [#22](https://github.com/keyforta/keyforta-property/issues/22)
authorizes the bounded correction of producer environment propagation in PR #13.
HAR-009 remains blocked at repair cycle three.

## Requirements

Every producer command must execute inside the dedicated cgroup and receive only
the explicit CI, harness, GitHub ref, HOME/XDG, and PATH values required for
deterministic validation. Runner credentials and unrestricted environment state
must not cross the launcher boundary.

## Failure

Exact-head GitHub run
[`35038390831`](https://github.com/keyforta/keyforta-property/actions/runs/35038390831)
created the cgroup, installed dependencies as the isolated producer, and proved
atomic shutdown. The subsequent validation command lost
`HARNESS_TASK_CONTRACT` at the outer `sudo sh` boundary, so the harness found
four changed task contracts. No reports were generated; packaging failed and
upload was skipped.

## Design

Pass the existing allowlisted values explicitly through the root launcher before
entering the producer command. Keep the cgroup assignment in the root wrapper,
the producer HOME/XDG isolation, sealed pnpm path, account lock, `cgroup.kill`,
`populated 0` proof, root-only control marker, and stop/package/upload outcome
chain. Do not use unrestricted `sudo -E` or preserve runner credentials.

## Tradeoffs

Explicit assignments are verbose but auditable and fail closed when a required
value is omitted. A helper abstraction is out of scope unless the existing
workflow cannot express the allowlist without duplication.

## Steps

1. Add a regression proving the nested producer receives HAR-010 and each
   allowlisted value through the cgroup launcher.
2. Correct the launcher at the owning CI command boundary.
3. Run focused lifecycle validation and canonical verification.
4. Publish exact-head evidence and require the protected retention canary.

## Risks

Broad environment preservation could expose runner state to untrusted code.
Incorrect launcher quoting could change argument boundaries or cgroup placement.
Tests must therefore inspect structured workflow commands and GitHub must execute
the final path on Ubuntu.
