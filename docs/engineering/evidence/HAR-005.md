# HAR-005 repair isolated CI tool access and cleanup

## Scope

Issue [#14](https://github.com/keyforta/keyforta-property/issues/14) approves a
bounded correction for the permission failures observed in PR #13 GitHub run
`35020322466`.

## Business invariant

Repository validation must run as a dedicated non-sudo producer without gaining
access to runner-home credentials or write access to runner-owned controls.

## Failure

The `Install dependencies` step failed with `env: 'pnpm': Permission denied`
because `pnpm/action-setup` installed pnpm below `/home/runner`, outside the
producer's reliable traversal boundary. Final cleanup also failed because plain
`rm` could not remove the intentionally read-only frozen retention control.
The report guard then failed closed because validation never produced reports;
that downstream behavior is expected and is not weakened by this correction.

## Design

Install pnpm below a run-specific directory in `/tmp`, make that installation
readable and executable but not writable by the producer, and retain the current
PATH supplied by `pnpm/action-setup`. Remove runner-owned source, snapshot, and
frozen-control directories with `sudo` during the final `always()` cleanup.

## Acceptance-test map

| Acceptance criterion | Requirement | Verification |
| --- | --- | --- |
| `AC-HAR-005-01` | The isolated producer can execute but not modify pnpm outside the runner home. | `harness/scripts/self-test/20-evidence-lifecycle.suite.mjs` and `pnpm harness:self-test` |
| `AC-HAR-005-02` | Final cleanup can remove the intentionally read-only frozen control. | `harness/scripts/self-test/20-evidence-lifecycle.suite.mjs` and GitHub CI |

## Security

The shared tool location is run-specific, runner-owned, and write-disabled for
the producer. Checkout credentials remain non-persistent. Cleanup privilege is
limited to deleting the three known runner-temporary evidence paths after scan
and upload handling.

## Threat model

Untrusted repository code runs as the producer and may try to alter tools or
retained evidence. It must not write the pnpm installation, frozen scanner,
runner-owned source, or retained snapshot. The workflow therefore separates
producer execution from runner-owned setup, scan, upload, and cleanup.

## Architecture

The correction stays inside the existing CI job and repository-neutral workflow
test. It changes no policy, schema, service, package, product runtime, data, or
deployment boundary.

## Bounded correction

Configure the existing pnpm setup action with a run-specific `/tmp` destination,
remove producer write permission from that installation, use privileged final
cleanup for runner-owned read-only paths, and add structured regressions for
both workflow properties. The first canonical run then identified that the
stacked HAR-005 contract listed only its four new files even though PR #13 still
contains six unchanged HAR-003 paths. The contract now authorizes the complete
ten-path PR inventory while HAR-005 changes remain limited to four paths.

## Repair cycle

HAR-005 used one correction cycle to authorize the complete stacked PR inventory
after canonical verification rejected the initial four-path contract. It remains
separate from HAR-003, which stays at its governed three-cycle limit.

## Tests

The focused workflow regressions failed against the PR #13 workflow and passed
after the bounded correction. A Linux Node 24 container confirmed the producer
can execute but cannot modify a tool with the configured modes and that
privileged cleanup removes a read-only control tree.

## Results

The full harness self-test passes with both HAR-005 regressions. Task contract,
classification, canonical verification, exact-head evidence, GitHub CI, and
independent review remain required.
