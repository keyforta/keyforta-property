# ENG-009 classification evidence artifacts

## Scope

Generate every classification artifact required by the checked-out evidence
policy from the task-specific Markdown evidence selected by the task contract.

## Requirements

Feature, bugfix, refactor, security, infrastructure, configuration,
documentation, dependency, operational, and emergency tasks must emit the
classification artifacts declared by the checked-out evidence policy.

## Risks

Generated records must retain path confinement, declared-reference checks,
SHA-256 binding, and substantive section validation.

## Unknowns

No product, runtime, data, infrastructure, or deployment behavior is affected.

## Design

Resolve the selected task evidence once, read artifact kinds from
`classificationRequirements`, and derive each record's sections from the
existing artifact section bindings.

## Tradeoffs

Policy-driven generation removes incomplete hardcoded classification branches.
An unknown artifact kind receives no sections and therefore fails existing
artifact validation instead of being accepted implicitly.

## Rollback

Revert the generic classification generator and regression. Existing
task-specific evidence selection remains independently functional.

## Steps

1. Generate policy-required classification artifact records.
2. Preserve the dependency compatibility helper.
3. Test feature, bugfix, existing classifications, and missing-section failure.

## Failure

Clean verification of WEB-001 generated its terminal verification report but
failed because the feature classification's required `acceptance-test-map` was
absent.

## Tests

The harness self-test verifies feature tasks generate `acceptance-test-map` and
bugfix tasks generate `failure-evidence` and `regression-test`, all bound to the
selected task evidence file.

## Results

The task contract and deterministic harness self-test pass. Canonical results
are recorded in the generated task report.

## Coverage

Regression coverage exercises policy-derived feature and bugfix artifact
generation while existing configuration and dependency checks remain active.

## Security

Artifact path confinement, symlink rejection, SHA-256 binding, declared-reference
checks, and substantive section validation remain unchanged.

## Accessibility

No user interface behavior changes.

## Architecture

The checked-out evidence policy remains the source of truth for classification
artifact requirements; the generator does not duplicate that mapping.

## Infrastructure

No infrastructure behavior changes.
