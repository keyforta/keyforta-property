# HAR-004 disable persisted CI checkout credentials

## Scope

Issue [#11](https://github.com/keyforta/keyforta-property/issues/11) approves a
bounded CI hardening that disables persisted checkout credentials before the
separate HAR-003 evidence-producer isolation is integrated.

## Business invariant

CI checkout credentials must not remain in repository configuration where later
workspace ownership changes could prevent reliable post-job cleanup.

## Design

Set `persist-credentials: false` on `actions/checkout@v7`. Parse the workflow and
require every checkout step to disable persistence in its own `with` mapping.
Do not alter checkout depth, checked-out SHA, permissions, policies, schemas,
product behavior, data, or deployment.

## Acceptance-test map

| Acceptance criterion | Requirement | Verification |
| --- | --- | --- |
| `AC-HAR-004-01` | CI checkout explicitly disables credential persistence. | `harness/scripts/self-test/20-evidence-lifecycle.suite.mjs` and `pnpm harness:self-test` |

## Security

The change reduces credential lifetime and removes dependence on a later
workspace write during checkout cleanup. Git operations requiring authentication
must supply credentials explicitly; this workflow performs no authenticated
Git operation after checkout.

## Threat model

A later CI step may change workspace ownership while repository credentials are
stored in `.git/config`. The checkout post-job action could then lose write
access and fail to remove those credentials. Disabling persistence prevents the
credential from entering repository configuration; this workflow performs no
authenticated Git operation after checkout.

## Architecture

The change remains inside the existing CI job and deterministic harness
self-test. It introduces no service, package, policy, schema, or runtime boundary.

## Rollback

Revert HAR-004 only after establishing an equivalent non-persistent checkout
credential control. No runtime, persistence, or deployment rollback applies.

## Steps
