# OPS-003 generated distribution artifact cleanup

## Authority

- Approved issue: https://github.com/keyforta/keyforta-property/issues/9
- Product-owner approval: https://github.com/keyforta/keyforta-property/issues/9#issuecomment-5687256353
- Task contract: `harness/tasks/OPS-003.json`
- Assigned route: `ROUTE-004`

## Scope

Stop tracking generated `dist/` directories, preserve local build behavior, and
verify that deployment images generate their required artifacts from source.
API runtime implementation and production deployment remain excluded.

## Invariant

Deployment artifacts must be reproducible from source and must not be treated as
authoritative repository inputs.

## Failure Evidence

The repository-wide ignore file covered only `dist/.openai/`. Git tracked 38
generated files under the root, admin-web, and portal-web `dist/` directories,
while a locally generated API `dist/` directory appeared as untracked output.
This made source-only review unreliable and allowed deployment checks to consume
workstation artifacts that are absent from a clean checkout.

## Design

Use Git's directory pattern `dist/` to ignore that directory name recursively.
Remove existing generated files from the index without deleting local copies.
Run a deterministic repository check before workspace checks to reject tracked
`dist/` files and verify representative root and nested outputs remain ignored.

## Regression Test

`apps/public-web/scripts/check-dist-tracking.mjs` reads the Git index and fails when any
path contains a `dist/` directory. It also asks Git to resolve the ignore rule
for root, API, admin-web, and portal-web output paths. The root `pnpm check`
command invokes this check before package checks.

## Deployment Verification

- `pnpm build:apps` passed. Public, admin, and portal web artifacts were
  regenerated without appearing as untracked files.
- The public-web Dockerfile built successfully from the repository context, and
  `/usr/share/nginx/html/index.html` existed in the runtime image.
- A no-cache API image build from a simulated clean checkout completed, but
  `/workspace/apps/api/dist/server.js` was absent. The current API build script
  only reports that the backend runtime is not configured, while the image
  declares that file as its command. This is a pre-existing deployment blocker,
  not repaired by OPS-003 because issue #9 excludes API runtime implementation.

## Rollback

Revert OPS-003 to restore the prior ignore rule, tracked generated files, and
root check command. No application, database, Azure resource, or deployed image
rollback is required because this task does not deploy or modify runtime source.

## Security

No authentication, authorization, secret, identity, or data-access behavior
changes. Removing generated bundles reduces duplicate review surfaces; canonical

## Data

## Observability

Canonical verification records the deterministic dist-tracking check. Docker

## Architecture

Application and deployment boundaries are unchanged. Docker remains responsible
for producing deployment artifacts from source during image construction.

## Results

Focused Git checks, all workspace builds, and public-web image verification
passed. Canonical verification passed repository policy, contract validation,
classification, lifecycle, agent governance, formatting, workspace checks,
architecture, secret scanning, documentation, harness self-tests, production

## Bounded Correction

The first canonical run rejected the task's infrastructure-and-operations work
area because the tracked removals are under web application paths and the new
check was initially under harness scripts. The correction moved the check into
public-web scripts and routed the task through the frontend owner. No runtime,
deployment template, harness implementation, or acceptance scope changed.
