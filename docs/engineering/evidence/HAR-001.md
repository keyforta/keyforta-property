# HAR-001: Ignore generated harness evidence reports

## Scope

Issue [#3](https://github.com/keyforta/keyforta-property/issues/3) approves a
bounded prerequisite fix for SHA-bound evidence generation. The task ignores
`harness/reports/` and removes four generated JSON reports that were
accidentally imported as source files. It also prevents the evidence manifest
from emitting undefined versions for tools the workspace does not declare. It
does not change harness policies, schemas, gate outcomes, product behavior, or
deployment.

## Business invariant

Verification evidence must remain deterministic and attributable to the exact
committed change. Generated reports cannot make an otherwise clean checkout
dirty before the harness evaluates its Git evidence context.

## Technical decision

- Apply the existing EDD rule that generated manifests are ignored locally and
  retained by CI as run artifacts.
- Keep durable task contracts and Markdown evidence in version control.
- Remove only generated files under `harness/reports/` from Git.
- Record Turbo and TypeScript versions only when those tools are declared by
  the root package manifest; always retain the declared package-manager version.
- Preserve every existing harness gate and policy unchanged.

## Acceptance-test map

| Acceptance criterion | Requirement | Verification |
| --- | --- | --- |
| `AC-HAR-001-01` | Generated manifests are ignored locally and retained by CI as run artifacts. | `git ls-files harness/reports` and `node harness/scripts/check-policy.mjs` |
| `AC-HAR-001-02` | Canonical verification produces valid SHA-bound evidence without dirtying tracked files. | `HARNESS_TASK_CONTRACT=harness/tasks/HAR-001.json pnpm verify` and `pnpm verify:evidence` |

## Configuration impact

Generated report files become ignored local and CI artifacts. Evidence tool
metadata contains only nonempty versions declared in the root package manifest.
No gate, schema, policy, runtime dependency, or deployment configuration changes.

## Security and data impact

No security control, authorization boundary, product data, production data, or
retention policy changes. Generated reports continue to be checked for secrets
by canonical verification and retained as CI artifacts according to the EDD
contract.

## Rollback

Revert the HAR-001 commits. This restores the prior tracked generated reports
and ignore behavior; no runtime or deployment rollback is required.

## Implementation evidence

- Added `harness/reports/` to `.gitignore`.
- Removed four generated JSON reports from version control.
- Updated manifest construction to omit undeclared tool entries and added a
  focused self-test that retains declared package-manager and Turbo versions.
- Preserved all harness policies, schemas, graders, and gate outcomes unchanged.
- The task contract, configuration classification, and `ROUTE-008` agent
  governance checks pass against exactly seven changed paths.
- Canonical verification and independent review are pending.
