# HAR-001: Ignore generated harness evidence reports

## Scope

Issue [#3](https://github.com/keyforta/keyforta-property/issues/3) approves a
bounded prerequisite fix for SHA-bound evidence generation. The task ignores
`harness/reports/` and removes four generated JSON reports that were
accidentally imported as source files. It also prevents the evidence manifest
from emitting undefined versions for tools the workspace does not declare and
scans generated JSON with the existing forbidden secret patterns. It does not
change harness policies, schemas, product behavior, or deployment.

## Business invariant

Verification evidence must remain deterministic and attributable to the exact
committed change. Generated reports cannot make an otherwise clean checkout
dirty before the harness evaluates its Git evidence context.

## Technical decision

- Apply the existing EDD rule that generated manifests are ignored locally and
  retained by CI as run artifacts.
- Keep durable task contracts and Markdown evidence in version control.
- Remove only generated files under `harness/reports/` from Git.
- Record Turbo and TypeScript versions only when those tools are declared by
  the root package manifest; always retain the declared package-manager version.
- Scan generated JSON reports after generation, remove unsafe files, and fail
  canonical verification before CI artifact retention.
- Run the retention guard terminally after all local report writes and again in
  CI after final evidence generation. Upload artifacts only when that guard
  succeeds, including for ordinary failed verification runs.
- Treat unreadable JSON as unsafe and avoid copying report filenames into
  retained failure details.
- Preserve every existing harness gate and policy unchanged.

## Configuration impact

Generated report files become ignored local and CI artifacts. Evidence tool
metadata contains only nonempty versions declared in the root package manifest.
Generated JSON is subject to a fail-closed terminal secret scan. CI retains
ordinary failure evidence only when the terminal guard succeeds. No schema,
policy, runtime dependency, or deployment configuration changes.

## Security and data impact

No authorization boundary, product data, production data, or retention policy
changes. Generated reports are checked after creation with the repository's
existing forbidden patterns. Unsafe or unreadable output removes the complete
evidence set and fails verification. CI runs the same guard after every report
producer and skips artifact upload if it fails.

## Rollback

Revert the HAR-001 commits. This restores the prior tracked generated reports
and ignore behavior; no runtime or deployment rollback is required.

## Implementation evidence

- Added `harness/reports/` to `.gitignore`.
- Removed four generated JSON reports from version control.
- Updated manifest construction to omit undeclared tool entries and added a
  focused self-test that retains declared package-manager and Turbo versions.
- Reused the repository secret patterns for generated JSON, with focused
  rejection coverage, unreadable-file coverage, and fail-closed evidence-set
  deletion before artifact retention.
- Added a terminal local guard and a terminal CI guard after final evidence
  generation; CI upload is conditional on the guard outcome.
- Preserved all harness policies and schemas unchanged.
- The task contract, configuration classification, and `ROUTE-008` agent
  governance checks pass.
- Canonical verification passed and generated SHA-bound evidence validated
  before the post-generation security control was added.

## Results

The cleanup, declared-tool filtering, and terminal generated-report security
control are implemented. Final canonical verification and repeated independent
review are pending the committed final repair.

## Failure

Independent reviews identified three bounded defects: stale path and result
claims plus undefined tool-version fields; ignored generated reports bypassing
the tracked-file secret scan; and a non-terminal scan that allowed later report
producers or unreadable files to escape the retention decision.

## Bounded correction

The corrections remove stale claims, filter undeclared tool versions, reuse the
existing forbidden patterns, fail closed on unreadable JSON, remove the complete
evidence set on findings, and run the guard terminally after all local and CI
report producers. No product code, harness policy, schema, or deployment changes.

## Repair cycle

Three changes-requested cycles were used. This is the final automated repair
cycle permitted by the EDD contract; any further finding blocks HAR-001 for
human disposition.
