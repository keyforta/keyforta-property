# HAR-002 canonical test-evidence mapping

## Scope

Issue [#7](https://github.com/keyforta/keyforta-property/issues/7) approves a
bounded harness correction that maps the canonical `workspace-checks` result to
the policy-facing `unit-integration-contract-tests` evidence name.

## Failure

WEB-004 canonical verification passed `pnpm check` under the
`workspace-checks` gate, then rejected its bugfix evidence manifest because the
classification policy requires a passing `unit-integration-contract-tests`
check that the canonical verifier never emits.

## Design

Derive the policy-facing test alias from the existing canonical workspace gate
inside evidence construction. A passed workspace result produces a passed
alias; failed, skipped, or missing workspace results remain non-passing. Use the
same source result for the manifest's aggregate `testResults` field.

## Tradeoffs

This preserves the stable canonical gate name while making its test semantics
explicit in generated evidence. It does not add a duplicate command or weaken
the policy requirement.

## Rollback

Revert HAR-002. No runtime, persistence, or deployment rollback is required.

## Steps

1. Add a focused manifest-construction regression for passing and non-passing
   workspace checks.
2. Emit the policy-facing alias and aggregate result from `workspace-checks`.
3. Run focused and canonical verification.

## Requirements

- Only a passed canonical workspace check may satisfy the test policy alias.
- Missing or non-passing workspace checks must remain fail closed.
- No evidence policy or schema changes are permitted.

## Tests

The harness lifecycle self-test verifies passing, failed, and missing workspace
check mappings. Canonical verification validates the generated HAR-002 evidence
manifest against the unchanged bugfix policy.

## Commit

HAR-002 is implemented on `fix/harness-test-evidence-mapping` for independent
review before merge.

## Files

- `harness/scripts/edd-lib.mjs` derives test evidence from the canonical
   workspace check.
- `harness/scripts/self-test/20-evidence-lifecycle.suite.mjs` covers passed,
   failed, and missing source results.
- `harness/tasks/HAR-002.json` and this document preserve governance and durable
   evidence.

## Traceability

Issue #7 maps through HAR-002 acceptance criterion `AC-HAR-002-01` to the
lifecycle self-test and unchanged bugfix evidence policy.

## Results

`pnpm harness:self-test` passes, including the focused fail-closed mapping
regression and all existing harness self-tests.

## Coverage

Automated coverage exercises passing, failed, and absent `workspace-checks`
results and validates both the policy-facing alias and aggregate test result.

## Security

No secret, authorization, data-access, or retention behavior changes. The alias
cannot turn a failed or missing result into passing evidence.

## Architecture

The correction remains inside harness evidence construction and its focused
self-test.

## Infrastructure

No infrastructure or deployment behavior changes.
