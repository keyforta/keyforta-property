# HAR-006 allow isolated CI workspace traversal

## Scope

Issue [#16](https://github.com/keyforta/keyforta-property/issues/16) approves a
bounded correction for PR #13 exact-head run `35022830837`.

## Business invariant

The dedicated non-sudo producer must reach its workspace without gaining list
or write access to runner-owned parent and sibling directories.

## Failure

Dependency installation failed with `EACCES: permission denied, scandir` for
`$GITHUB_WORKSPACE`. Transferring workspace ownership did not grant traversal
through the parent chain under `/home/runner`.

## Design

Copy the runner-owned checkout into a run-specific `/tmp` directory before
untrusted validation, transfer only that copy to `keyforta-ci`, and run every
producer step from the copied workspace. Keep the original checkout and all
runner-home ancestors runner-owned. Seal reports from the producer copy after
locking and terminating the producer, then remove the copy during final cleanup.

## Acceptance-test map

| Acceptance criterion | Requirement | Verification |
| --- | --- | --- |
| `AC-HAR-006-01` | The producer can scan an owned copy of the checked-out commit. | `harness/scripts/self-test/20-evidence-lifecycle.suite.mjs` and canonical verification |
| `AC-HAR-006-02` | The producer requires no runner-home traversal or sibling access. | Structured workflow regression and GitHub CI |

## Security

The producer receives ownership only of its run-specific workspace copy. No ACL
or mode is broadened on runner-home ancestors, siblings, the original checkout,
the frozen scanner, report source, or retained snapshot.

## Threat model

Untrusted repository code runs as `keyforta-ci` and must not need access through
runner-home ancestors or to predictable siblings such as `_temp`. A dedicated
workspace below `/tmp` removes that traversal dependency while preserving the
original runner-owned checkout for action post-processing.

## Architecture

The correction stays inside the existing ephemeral CI job and deterministic
workflow test. It changes no policy, schema, runtime, data, infrastructure, or
deployment boundary.

## Bounded correction

The initial execute-only ACL design passed its focused Linux probe, but security
review found two structural issues: ACL mask recalculation could affect existing
entries, and ancestor traversal permits lookup of predictable readable siblings.
The approved bounded correction replaces ACLs with a run-specific producer-owned
workspace copy and binds every unprivileged step, report handoff, and cleanup to
that path.

## Repair cycle

HAR-006 used one correction cycle to replace ancestor ACLs with an isolated
workspace copy after security review. HAR-003 and HAR-005 remain unchanged at
their governed three-cycle limits.

## Tests

The focused regression failed before the workflow correction and passed after
it. The initial Linux ACL probe passed its narrow traversal assertions before
security review rejected that design. A revised Linux Node 24 probe verified
that copied Git metadata is usable, producer writes stay in the isolated `/tmp`
workspace, and the original runner-home checkout remains unreachable.

## Results

The full harness self-test, HAR-006 contract validation, and 12-path bugfix
classification pass. Canonical verification, exact-head evidence, independent
review, and GitHub CI remain required.
