# HAR-006 allow isolated CI workspace traversal

## Scope

Issue [#16](https://github.com/keyforta/keyforta-property/issues/16) approves a
bounded correction for PR #13 exact-head run `35022830837`.

## Business invariant

The dedicated non-sudo producer must reach its workspace without gaining list
or write access to runner-owned parent and sibling directories.

## Failure

Dependency installation failed with `EACCES: permission denied, scandir` for
`$GITHUB_WORKSPACE`. Transferring workspace ownership did not grant traversal
through the parent chain under `/home/runner`.

## Design

Resolve the three workspace ancestors from the trusted `$GITHUB_WORKSPACE`
environment value and apply a named-user execute-only ACL for `keyforta-ci` to
each ancestor. Keep existing owner, group, and other mode bits unchanged. The
workspace itself remains producer-owned.

## Acceptance-test map

| Acceptance criterion | Requirement | Verification |
| --- | --- | --- |
| `AC-HAR-006-01` | The producer can traverse the parent chain and scan its workspace. | `harness/scripts/self-test/20-evidence-lifecycle.suite.mjs` and Linux permission probe |
| `AC-HAR-006-02` | Parent directories remain non-listable and non-writable to the producer. | Linux permission probe and GitHub CI |

## Security

A named-user `--x` ACL grants path traversal only. It does not grant directory
listing, file reads, or writes; access to descendants still depends on their
own permissions. No mode bits are broadened for other local identities.

## Threat model

Untrusted repository code runs as `keyforta-ci`. It needs to traverse the runner
home, work root, and repository parent to enter its owned workspace, but must not
enumerate or alter those runner-owned ancestors or sibling repositories.

## Architecture

The correction stays inside the existing ephemeral CI job and deterministic
workflow test. It changes no policy, schema, runtime, data, infrastructure, or
deployment boundary.

## Bounded correction

Add execute-only ACLs for the producer to the three workspace ancestors and a
structured regression requiring that exact bounded command.

## Repair cycle

HAR-006 begins at repair cycle zero. HAR-003 and HAR-005 remain unchanged at
their governed three-cycle limits.

## Tests

The focused regression failed before the workflow correction and passed after
it. A Linux Node 24 probe using real `setfacl` verified that the producer can
enter and write its owned workspace while listing and writing each of the three
runner-owned ancestors fail.

## Results

The full harness self-test, HAR-006 contract validation, and 12-path bugfix
classification pass. Canonical verification, exact-head evidence, independent
review, and GitHub CI remain required.
