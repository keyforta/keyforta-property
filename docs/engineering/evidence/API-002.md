# API-002: KEYFORTA API runtime and public property discovery

## Scope

Issue [#1](https://github.com/keyforta/keyforta-property/issues/1) approves the
full source API migration through bounded KEYFORTA adaptation slices. API-002
ports only the reusable Fastify runtime patterns and canonical anonymous property
reads. Authentication, protected writes, leases, payments, documents, database
migrations, and deployment activation remain outside this task.

The source revision is `39eab863e83d684c113f16f33e0a3b92f9ee8188`.
KEYFORTA contracts and accepted ADRs take precedence over source routes and
behavior.

## Business invariant

Anonymous discovery may return only published, public-safe property data. It
must not expose organization membership, private documents, tenant data,
financial records, unpublished inventory, or an unrestricted organization
selector.

## Technical decision

- Keep the API in the existing `apps/api` modular-monolith boundary.
- Use Fastify with dependency-injected gateways so transport does not own
  persistence.
- Validate public input with schemas exported by `packages/contracts`.
- Expose canonical `/api/v1/properties` list and detail routes rather than
  retaining source-specific listing paths.
- Treat those GET operations as the approved public-discovery equivalent in
  [`ADR-011`](../../adr/ADR-011-public-property-discovery-route.md); protected
  mutations on the same resources retain global bearer security.
- Preserve request correlation IDs in response headers and sanitized errors.
- Keep synthetic development data behind a gateway; production PostgreSQL work
  requires a later database-owned task.
- Keep the frontend static fallback and all deployment workflows inactive.

## Security and data impact

This slice adds no authentication bypass because it adds no protected route.
The gateway contract itself returns a public projection and cannot return a
domain or persistence record. Tests cover unpublished-record exclusion,
malformed filters, missing records, unavailable dependencies, and sanitized
internal failures.

No production or personal data is used. Fixtures are synthetic. No database
schema, retention behavior, payment boundary, or financial history changes.

does not depend on this API until a separately approved integration task.

`HARNESS_TASK_CONTRACT=harness/tasks/API-002.json pnpm verify:agents`, which
reported `API-002 harness/reports/ requires workArea governance-and-harness`.
